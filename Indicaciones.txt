PROYECTO: INVESTIGACIÓN II - API GATEWAY CON NESTJS
===============================================================================

CONTEXTO:
Tengo una investigación universitaria que requiere implementar un ejemplo 
funcional de API Gateway usando NestJS, Docker y Docker Compose.

El objetivo es demostrar que dos o más servicios desarrollados por el equipo 
se comunican o coordinan entre sí utilizando API Gateway.

===============================================================================
REQUISITOS DEL PROYECTO
===============================================================================

1. TEMA: API Gateway
2. TECNOLOGÍA: NestJS (Node.js framework)
3. SERVICIOS: Mínimo 2 servicios desarrollados por el equipo
4. INFRAESTRUCTURA: Docker + Docker Compose
5. EJECUCIÓN: Script run.ps1 (Windows) o run.sh (Linux/Mac)

DESCRIPCIÓN DE CADA SERVICIO
===============================================================================

-------------------------------------------------------------------------------
SERVICIO 1: API GATEWAY (puerto 3000)
-------------------------------------------------------------------------------

RESPONSABILIDAD:
- Recibir TODAS las peticiones HTTP de los clientes
- Actuar como punto de entrada único
- Redirigir (proxy) las peticiones al microservicio correspondiente
- Registrar (log) cada petición que pasa por él
- Devolver la respuesta del microservicio al cliente

ENDPOINTS DEL API GATEWAY:
- GET  /api/products          → Redirige a product-service:3001/products
- GET  /api/products/:id      → Redirige a product-service:3001/products/:id
- POST /api/products          → Redirige a product-service:3001/products
- PUT  /api/products/:id      → Redirige a product-service:3001/products/:id
- DELETE /api/products/:id    → Redirige a product-service:3001/products/:id
- GET  /api/health            → Verifica que el gateway está vivo

CARACTERÍSTICAS:
- Usar HttpService de @nestjs/axios para hacer las peticiones HTTP
- Usar ConfigService para leer la URL del microservicio desde variables de entorno
- Implementar un Logger para registrar cada petición (método, URL, timestamp)
- Implementar un interceptor para medir el tiempo de respuesta
- Manejar errores del microservicio y devolver respuestas apropiadas

VARIABLES DE ENTORNO:
- PORT=3000
- PRODUCT_SERVICE_URL=http://product-service:3001

LOGS ESPERADOS:
Cada petición debe registrar algo como:
[API-GATEWAY] 2026-01-15 10:30:45 - GET /api/products - Redirigiendo a http://product-service:3001/products

-------------------------------------------------------------------------------
SERVICIO 2: PRODUCT SERVICE (puerto 3001)
-------------------------------------------------------------------------------

RESPONSABILIDAD:
- Gestionar productos (CRUD)
- Almacenar productos en memoria (no necesita base de datos)
- Devolver respuestas JSON

ENDPOINTS DEL PRODUCT SERVICE:
- GET    /products          → Listar todos los productos
- GET    /products/:id      → Obtener un producto por ID
- POST   /products          → Crear un nuevo producto
- PUT    /products/:id      → Actualizar un producto
- DELETE /products/:id      → Eliminar un producto
- GET    /health            → Verificar que el servicio está vivo

MODELO DE DATOS (Product):
{
  id: number,
  name: string,
  description: string,
  price: number,
  stock: number,
  createdAt: Date
}

DATOS INICIALES (seed):
[
  { id: 1, name: "Laptop HP", description: "Laptop 15 pulgadas", price: 800, stock: 10 },
  { id: 2, name: "Mouse Logitech", description: "Mouse inalámbrico", price: 25, stock: 50 },
  { id: 3, name: "Teclado Mecánico", description: "Teclado RGB", price: 120, stock: 30 }
]

VARIABLES DE ENTORNO:
- PORT=3001

LOGS ESPERADOS:
[PRODUCT-SERVICE] 2026-01-15 10:30:45 - GET /products - Listando productos
[PRODUCT-SERVICE] 2026-01-15 10:30:46 - POST /products - Creando producto: Laptop HP

DOCKER COMPOSE
-------------------------------------------------------------------------------
Ubicación: /docker-compose.yml

Contenido esperado:
- Servicio api-gateway (puerto 3000:3000)
- Servicio product-service (puerto 3001:3001)
- Red interna compartida (para que se comuniquen por nombre de servicio)
- Variables de entorno desde .env
- depends_on: api-gateway depende de product-service
- Healthchecks para ambos servicios

EJEMPLO DE ESTRUCTURA:
services:
  product-service:
    build: ./product-service
    container_name: product-service
    ports:
      - "3001:3001"
    environment:
      - PORT=3001
    networks:
      - api-gateway-network
    healthcheck:
      test: ["CMD", "wget", "--quiet", "--tries=1", "--spider", "http://localhost:3001/health"]
      interval: 10s
      timeout: 5s
      retries: 5

  api-gateway:
    build: ./api-gateway
    container_name: api-gateway
    ports:
      - "3000:3000"
    environment:
      - PORT=3000
      - PRODUCT_SERVICE_URL=http://product-service:3001
    depends_on:
      product-service:
        condition: service_healthy
    networks:
      - api-gateway-network

networks:
  api-gateway-network:
    driver: bridge
